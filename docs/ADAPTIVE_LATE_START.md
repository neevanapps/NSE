# Late-start observation and deployment performance

User-authorized policy, 2026-10-06. Watch-only remains in force; no paper or real orders are enabled.

The 09:30 estimator normally uses observed futures volume from 09:15–09:30. A conservative coverage check requires a persisted futures tick in each of those 15 minutes and positive observed opening volume. This checks collection coverage, not proof of every exchange update. A late process start with complete stored ticks still uses the normal opening estimate.

When coverage is missing, use the median positive observed opening volume from all prior validated historical seeds and prior live sessions with 15 covered minutes. Exclude today, future sessions and all median-fallback sessions. Apply the existing V1 day-volume projection and lot rounding to this median. Freeze the input, sample count, measured partial volume, coverage and observation start in the daily session. Do not refreeze an existing daily session when history or source data changes. No eligible history means no invented estimate.

Fallback bars begin at the first persisted futures tick at or after 09:30. That tick establishes a cumulative-volume baseline; offline volume does not create artificial bars. Missing 09:30 futures/options quotes do not get synthetic residual anchors. Fallback days are excluded from subsequent strong-threshold and median calibration pools. Dashboard and screenshots disclose the historical-median mode; it is operational continuity, not historically validated trading equivalence.

Readiness requires ten consecutive, exact-volume, contiguous completed futures bars with positive finite OHLC, consistent price bounds, trade updates and nonnegative elapsed time. Zero-duration exact split bars remain valid event bars. An incomplete bar does not count. Each bar is checked only against bars at or before its sequence. Weak2 actionable observations obey this gate; future paper/order consumers must also obey `AdaptiveReadinessPolicy` and their own option availability, stale-data, execution and risk gates. This minimum gate is not a sufficient trading entry condition. Displayed early rows remain provisional. Verified reconstructed bars count after restart, as selected by the user; missing history requires ten actually observed bars. Recovery/corruption failures never become ready merely because rows exist.

AddLateStartProvenance adds nullable metadata for legacy sessions and a false default for fallback mode. Existing valid sessions retain their frozen definition. A previously frozen zero-opening session fails explicitly rather than being silently rewritten; repair requires an explicit reviewed rebuild.

Deployment builds Release once with exact SHA/branch/build time, runs the full unit suite against those binaries, and publishes without rebuilding. Changed files are packed into one delta ZIP and transferred before stopping each remote service, then extracted without deleting installed local settings or runtime output. Matching version-specific Chromium installations are reused. Step durations are printed. Tests, clean-worktree and expected-master-SHA guards remain. Package tests cover nested Playwright paths, changed files only, preserved VM secrets and unsafe-path rejection. Actual WinRM speed gains and Windows pre-live readiness require VM measurement.

Do not deploy Host during today's active market solely to enable this feature. Use the validated merged master SHA at an agreed maintenance window, deploy both applications and verify migration/runtime identities, warm-up labels and restart behavior. Median fallback behavior has automated synthetic coverage; its trading performance remains unvalidated.
